# JSON Parser Tool Documentation & Usage Guide

The **JSON Parser** node parses and extracts structured JSON content from local disk files, remote HTTP endpoints, or upstream Agent responses. It converts unstructured or raw text into validated JSON objects with typed output variables according to a defined **Zod Output Schema**.

## 1. Overview & Architecture

When a JSON Parser node executes:
- **Source Resolution**: The node checks the selected `sourceType`:
  - `path`: Reads the file content from the local runner filesystem.
  - `url`: Makes an HTTP GET request to the target URL and extracts the body.
  - `agent`: Reads raw string or object responses from an upstream Agent node.
- **Parsing**: Unescapes strings, strips extraneous markdown code blocks (such as ````json ... ````), and parses the text into an object.
- **Output Typing**: Emits the parsed object under the `value` handle, exposing schema properties for downstream flow blocks.

## 2. Node Inputs & Configuration

| Input Field | Type | Required | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `sourceType` | `radio` | Yes | `"path"` | Origin of the JSON payload: `"path"`, `"agent"`, or `"url"`. |
| `filePath` | `text` | Conditional | `""` | Absolute filesystem path (e.g. `/data/config.json`). Visible when `sourceType` is `"path"`. |
| `agentId` | `select` | Conditional | `null` | Target Agent instance from `/api/agents`. Visible when `sourceType` is `"agent"`. |
| `targetUrl` | `text` | Conditional | `""` | Remote HTTP/HTTPS URL returning JSON. Visible when `sourceType` is `"url"`. |
| `outputType` | `code` (ts) | Yes | `z.object({...})` | Zod schema defining the expected object structure. |

## 3. Source Types

### File Path Mode
Loads a static or generated file from the backend runner filesystem.

```json
{
  "sourceType": "path",
  "filePath": "/Users/faraz/builder/files/extracted/config.json"
}
```

### Agent Output Mode
Used to parse unstructured text generated by an upstream LLM Agent into clean JSON. If the LLM included conversational text or markdown code blocks, the parser strips the markers and extracts the JSON content.

```json
{
  "sourceType": "agent",
  "agentId": "agent_audit"
}
```

### Remote URL Mode
Fetches remote JSON feeds, REST APIs, or public webhooks directly.

```json
{
  "sourceType": "url",
  "targetUrl": "https://api.github.com/repos/octocat/Hello-World"
}
```
*Note: Supports variable interpolation in `targetUrl` (e.g. `https://api.example.com/users/{{input.userId}}`).*

## 4. Output Schema (Zod)

Specify the Zod schema matching the expected JSON data:

```typescript
z.object({
  id: z.string(),
  name: z.string(),
  status: z.enum(["active", "pending", "closed"]),
  metrics: z.object({
    requests: z.number(),
    latencyMs: z.number()
  }),
  tags: z.array(z.string())
})
```

## 6. Real-World Examples & Recipes

### Recipe 1: Fetch and Parse Remote API Data
```json
{
  "sourceType": "url",
  "targetUrl": "https://dummyjson.com/products/1",
  "outputType": "z.object({\n  id: z.number(),\n  title: z.string(),\n  price: z.number(),\n  rating: z.number(),\n  stock: z.number(),\n  brand: z.string()\n})"
}
```

### Recipe 2: Parse Extracted Configuration File
```json
{
  "sourceType": "path",
  "filePath": "{{variables.extractedFilePath}}",
  "outputType": "z.object({\n  version: z.string(),\n  endpoints: z.array(z.string()),\n  enabled: z.boolean()\n})"
}
```

## 7. Troubleshooting & Best Practices

1. **Markdown Wrapping**: The parser automatically trims markdown ```` ```json ```` fences from LLM responses, but ensuring the LLM is instructed to respond strictly with JSON prevents edge-case parsing errors.
2. **Handling URL Errors**: If using `sourceType: "url"`, verify the endpoint returns HTTP 200 and standard JSON headers (`Content-Type: application/json`).
3. **Array vs Object**: If the source JSON is a root array (e.g. `[{...}, {...}]`), set your Zod schema to `z.array(...)` so downstream property references are correctly typed.
